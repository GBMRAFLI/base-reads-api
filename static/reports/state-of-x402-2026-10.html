State of x402 on Base — October 2026

A snapshot of the public x402 Bazaar, shared so developers and buyer agents can see the market as it is today. Facts only: no ratings, no verdicts, and no endpoint, host or wallet is named.

Snapshot: 2026-10-21 10:10 UTC (17:10 WIB) · Source: public CDP x402 Bazaar discovery API · Method: § Method · Data: aggregate_stats.csv, liveness_sample_200.csv

Thanks to the CDP team and everyone listing services in the Bazaar: an open, queryable index is what makes a report like this possible.

Every figure below carries its snapshot date, sample size (n) and method ID (M1–M4, defined in § Method).

4. Payout wallets (payTo) on Base

Snapshot 2026-10-21 · n = 27,803 listings with a Base option · Method M3 · data

  • 1,706 distinct Base payTo addresses.
  • 268 payTo addresses receive for listings on 2+ different hosts; 22 on 10+ hosts; the largest single payTo is shared by 101 hosts.
  • The largest single payTo is attached to 1,630 listings.

Shared payout wallets are common and usually expected (platforms, marketplaces, operators running several domains). We publish counts only; no address is named, and wallet sharing is a fact to be aware of, not a signal about any operator.

The 3 differences have ordinary explanations as well (wallet rotation, an index entry not yet refreshed). We do not name them. The takeaway is simple: a directory listing is a snapshot, and the live 402 is what a buyer actually pays.

One mechanism that can help

Comparing the live challenge with the listing before signing is cheap, and anyone can do it. We built Pre-pay Check to package exactly these facts for agents: GET /x402/preflight?url=… ($0.01 USDC on Base) returns an Ed25519-signed JCS attestation with pass / fail / not_applicable checks (challenge validity, USDC on Base, payTo contract check, reachability and latency, payTo vs listing). It returns facts, not scores. Attestations can be verified offline with the published issuer key: /llms.txt

Method

  • M1 — Full crawl. Public CDP x402 Bazaar discovery API, paged ?limit=1000&offset=n until exhausted, 2026-10-21 10:10 UTC. Counts are taken directly from listing metadata (accepts, x402Version, call counters, last-called timestamps).
  • M2 — Base price. For each listing, the cheapest option with network eip155:8453 and asset USDC (0x8335…2913); price = amount / 10^6.
  • M3 — payTo sharing. Lower-cased Base payTo addresses grouped by resource hostname. Only counts are published.
  • M4 — Live sample. 200 GET listings drawn at random; one unpaid HTTPS GET each, UA x402-ecosystem-survey/0.1, 8 concurrent, 5 s timeout, no payment signatures sent. Live Base payTo compared with the listed payTo.
  • Public files (aggregate_stats.csv, liveness_sample_200.csv): aggregate_stats.csv (aggregate counts only) and liveness_sample_200.csv (sample index, status, latency, header present, match true/false). Neither contains payTo addresses, hosts, URLs or raw listings. Raw crawl data is not published.
  • Limits: one index, one point in time; call counters are as reported by the index; the live sample is small.
