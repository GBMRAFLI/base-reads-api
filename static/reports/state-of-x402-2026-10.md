## One mechanism that can help
Comparing the live challenge with the listing before signing is cheap, and anyone can do it. We built Pre-pay Check to package exactly these facts for agents: `GET /x402/preflight?url=…` ($0.01 USDC on Base) returns an Ed25519-signed JCS attestation with pass / fail / not_applicable checks (challenge validity, USDC on Base, payTo contract check, reachability and latency, payTo vs listing). It returns facts, not scores. Attestations can be verified offline with the published issuer key: /llms.txt

## Method
<a id="method"></a>
- <a id="m1"></a>**M1 — Full crawl.** Public CDP x402 Bazaar discovery API, paged `?limit=1000&offset=n` until exhausted, 2026-10-21 10:10 UTC. Counts are taken directly from listing metadata (`accepts`, `x402Version`, call counters, last-called timestamps).
- <a id="m2"></a>**M2 — Base price.** For each listing, the cheapest option with network eip155:8453 and asset USDC (0x8335…2913); price = `amount` / 10^6.
- <a id="m3"></a>**M3 — payTo sharing.** Lower-cased Base payTo addresses grouped by resource hostname. Only counts are published.
- <a id="m4"></a>**M4 — Live sample.** 200 GET listings drawn at random; one unpaid HTTPS GET each, UA `x402-ecosystem-survey/0.1`, 8 concurrent, 5 s timeout, no payment signatures sent. Live Base payTo compared with the listed payTo.
- **Public files** ([aggregate_stats.csv](/reports/data/aggregate_stats.csv), [liveness_sample_200.csv](/reports/data/liveness_sample_200.csv)): `aggregate_stats.csv` (aggregate counts only) and `liveness_sample_200.csv` (sample index, status, latency, header present, match true/false). Neither contains payTo addresses, hosts, URLs or raw listings. Raw crawl data is not published.
- **Limits:** one index, one point in time; call counters are as reported by the index; the live sample is small.
